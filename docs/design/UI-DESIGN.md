# 界核 / REALM 美术与界面设计规范

> 文档性质：视觉与交互规范，不记录当前完成进度。当前进度只以根目录 [`STATUS.md`](../../STATUS.md) 为准。
> 规范名称：**纸墨纪事 / Paper Chronicle**。

## 1. 视觉定位

界核不是泛用聊天工具，也不是霓虹科幻控制台。它应像一份仍在生长的世界档案：有纸张的温度、编辑排版的秩序、规则表格的精确，以及少量朱印般的行动强调。

关键词：

```text
纸张 / 墨线 / 朱印 / 档案 / 编年史 / 克制 / 精确 / 无圆角
```

需要避免：

```text
玻璃拟态 / 大面积渐变 / 胶囊按钮 / 过度圆角 / 霓虹光晕
游戏 HUD 堆叠 / 大量图标 / 浮夸动效 / 密集设置面板
```

## 2. 核心原则

### 2.1 直角是结构，不是装饰

- 所有卡片、输入框、按钮、标签、弹窗和导航项默认 `border-radius: 0`。
- 状态差异依靠边线、底色、排版和小面积色块表达，不靠不同圆角。
- 新组件不得私自引入圆角风格。

### 2.2 先读故事，再看系统

- 叙事正文拥有最高阅读舒适度。
- 世界时间、角色类型、版本和状态使用更小、更理性的字体。
- 控制面信息必须后退，不能盖过角色发言。

### 2.3 少即是好

- 普通玩家每个视图只保留一个清晰主动作。
- 默认不暴露 Token、缓存、ACL、检索权重、模型参数等底层选项。
- 高级能力进入 Creator/DM 专用视图，不堆进聊天主界面。

### 2.4 色彩必须有语义

- 朱红只用于主动作、玩家轨迹、焦点和高优先提示。
- 苔绿只用于正常、在线、已完成和系统稳定态。
- 金棕只用于等待、未决、秘密域提示和需要留意但非错误的状态。
- 不用大面积高饱和色填满内容卡片。

## 3. 设计 Tokens

### 3.1 颜色

| Token | 色值 | 用途 |
|---|---|---|
| `--paper` | `#eee9de` | 应用背景、纸张基底 |
| `--paper-soft` | `#f7f4ec` | 主内容面、卡片浅底 |
| `--paper-deep` | `#ded7c7` | 次级块、头像底、结构分区 |
| `--white` | `#fffdf8` | 发言卡片和输入区 |
| `--ink` | `#20231f` | 主文本、顶栏、主按钮 |
| `--ink-soft` | `#55594f` | 次级文本 |
| `--ink-faint` | `#7a7c72` | 元数据、说明、弱标签 |
| `--line` | `#b8b2a5` | 普通边线与分隔线 |
| `--line-dark` | `#77766d` | 强结构线和输入边框 |
| `--accent` | `#b94c36` | 朱红主强调 |
| `--accent-deep` | `#893524` | Hover、错误和深强调 |
| `--moss` | `#546552` | 正常、在线和规则完成 |
| `--gold` | `#9c7438` | 等待、秘密、未决 |
| `--semantic-environment` | `#3f6770` | 环境描写文字 |
| `--semantic-story` | `#70556b` | 剧情描写文字 |
| `--semantic-fact` | `#8a672d` | 关键事实文字 |
| `--semantic-action` | `#526b50` | 动作行为文字 |
| `--semantic-dialogue` | `#9b4938` | 台词文字 |

色彩规则：

- 正文在 `paper / white` 上使用 `ink`。
- 次级说明至少使用 `ink-soft`；极小元数据才使用 `ink-faint`。
- 错误提示使用浅朱红底 + 深朱红字 + 1px 边线。
- 任何新状态色必须先说明语义，不能只为“更好看”添加。

### 3.2 字体

```css
--font-sans: Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-serif: "Noto Serif SC", "Songti SC", STSong, serif;
--font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

职责：

- Serif：品牌、世界名、故事名、记录标题、角色名、叙事正文。
- Sans：按钮、表单、普通说明、系统消息和操作反馈。
- Mono：Eyebrow、时间、编号、状态、版本、快捷键和技术元数据。

推荐字号层级：

| 层级 | 字号 | 字体 | 用途 |
|---|---:|---|---|
| Display | `25–34px` | Serif | 当前 Record 标题 |
| Title | `18–21px` | Serif | 世界、场景和卡片主标题 |
| Name | `12–14px` | Serif | 角色名与小标题 |
| Narrative | `13–14px` | Serif | 发言与旁白正文，行高约 `1.9` |
| UI | `11–14px` | Sans | 表单、按钮和普通信息 |
| Meta | `8–10px` | Mono | 时间、状态、标签与编号 |

### 3.3 间距

使用 4px 基础节奏，优先从以下尺度选择：

```text
4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 / 32 / 40 / 52
```

- 内容卡内边距：桌面 `16–20px`，移动端 `14px`。
- 同类卡片间距：`14–17px`。
- 大分区内边距：`20–24px`，主时间线水平最大 `52px`。
- 不使用无规律的零碎间距制造对齐。

### 3.4 边线与阴影

- 默认边线：`1px solid var(--line)`。
- 强结构：`1px solid var(--line-dark)`。
- 主卡片阴影：`3px 3px 0 rgba(32, 35, 31, 0.06–0.08)`。
- 选中导航：`2px 2px 0 rgba(32, 35, 31, 0.12)`。
- 阴影必须是短距离硬阴影，不使用大范围模糊漂浮感。

## 4. 页面结构

### 4.1 桌面

```text
68px 顶栏
251px 世界导航 | 弹性记录主区 | 298px 场景检查器
```

- 主叙事列始终拥有最大视觉权重。
- 时间线正文建议最大宽度 `780px`。
- 左侧表达世界 → 故事 → 记录层级。
- 右侧只承载当前场景、在场角色、视角和少量关键状态。

### 4.2 平板

- `980px` 以下转为双栏：左侧导航 + 主记录。
- 场景检查器移动到主记录下方，使用两列卡片。
- 导航可 Sticky，但不得遮挡内容。

### 4.3 手机

- `720px` 以下改为纵向结构。
- 顶栏压缩为品牌 + 当前视角。
- 左侧导航只保留当前 World/Story 概览，隐藏完整 Record 列表。
- 输入区固定在底部，但不得遮住最后一条事件。
- 卡片仍保持直角、细线和纸张质感，不改成移动端气泡聊天。

## 5. 组件规范

### 5.1 顶栏

- 墨黑底，纸白字。
- 品牌印章使用朱红方块，不加圆角。
- 面包屑在空间不足时截断，不换行堆叠。
- 同步与视角状态使用细边框矩形标签，不使用胶囊。

### 5.2 导航卡

- 默认无完整外框，只通过留白与短轨道区分。
- 当前项使用纸白底、深边线、硬阴影和朱红轨道。
- 层级靠字号、字体和位置表达，不靠更多颜色。

### 5.3 事件时间线

- 使用纵向轴线与小菱形节点，不使用消息气泡尾巴。
- 发言卡统一直角矩形。
- 旁白：较深纸色底、Serif 斜体正文。
- 玩家：左侧 3px 朱红轨道。
- 规则/系统：浅苔灰底、Sans 正文、无浮动阴影。
- Pending：虚线边框与降低不透明度。
- Failed：朱红边线与明确的未提交说明。

### 5.4 行动框与行动面板

- 文本输入仍是唯一主动作；玩家不需要格式化输入。
- 输入框左侧使用直角“＋ 行动”入口，展开后只显示当前服务端授权的可用项。
- 面板按技能、物品、姿态和场景分层；空分类不显示，不能用禁用按钮制造虚假丰富度。
- 选择项以单个紧凑纸片显示在输入框上方，可随时移除；不得把完整工具参数暴露给普通玩家。
- 点击选项可以在空输入框中填入自然语言建议，但不得覆盖玩家已经输入的正文。
- 选择项失败或写入冲突时，正文与选择必须一起保留。
- 面板使用纸白底、细边线和文字强调；不使用浮夸技能图标、彩色大底块或游戏 HUD。

语义片段：

- 环境、剧情、事实、动作、台词只使用五种低饱和文字色；
- 不为片段添加底色、左轨、边框或常驻类型标签，保持原有纸墨卡片阅读感；
- 同一 Event 内按原文顺序连续排版，动作和引号内台词必须分别着色；
- 不显示横线或特殊字符作为语音分隔符；DOM 节点本身即隐式边界；
- 类型通过机器属性、悬停说明和无障碍名称表达，不进入正文复制或未来 TTS 文本；
- OOC/秘密颜色仍由 Event 外框表达，不能被片段色覆盖。

### 5.4 输入区

- Textarea 与发送按钮拼成一个连续矩形。
- 主按钮墨黑底，Hover 转深朱红。
- Focus 使用左侧内嵌朱红线与全局 2px Focus Ring。
- 只保留一个主动作“送出”；快捷键作为弱元数据展示。

### 5.5 检查器卡片

- 纸白底、深边线、硬阴影。
- 事实字段用两列定义列表表达。
- 状态标签尺寸小、位置稳定，不与标题争夺注意力。
- 长说明优先一段短文，不堆一组 Toggle。

### 5.6 按钮

- Primary：墨黑底、纸白字；Hover 深朱红。
- Secondary：透明或纸白底、深边线、墨色字。
- Destructive：深朱红底；只用于明确不可逆操作。
- Disabled：中性灰底，不能只依靠透明度表达。
- 按钮最小触控高度建议 `40px`；紧凑元操作也不得低于 `32px`。

### 5.7 标签与状态

- 矩形细边框，`8–10px` Mono 或 `10–11px` Sans。
- 标签是说明，不应看起来像主要按钮。
- 同一行最多出现 3 个状态标签，更多信息进入详情。

## 6. 视角、秘密与控制面

新增信息边界功能时使用以下视觉语义：

| 类型 | 视觉表达 |
|---|---|
| Public | 默认纸白卡与普通边线 |
| Scene | 小型“当前场景”Mono 标签 |
| Character private | 朱红左轨 + “仅你所知”标签 |
| Restricted group | 金棕细线或角标 + 秘密域名称；正文不大面积染色 |
| OOC omniscient | 虚线框、`◐` 图形和明确“OOC/角色未知”说明 |
| DM/control | 浅苔灰系统卡；绝不混入普通叙事卡 |

规则：

- 不用模糊、遮罩或“点一下揭晓”代替真正 ACL。
- 上帝视角看到秘密时必须明确标注“角色未知”，避免玩家误认为角色可用。
- 普通玩家不得看到“过滤了 3 条秘密”之类侧信道信息。
- Manifest、Prompt、Cache Key 和内部 ACL ID 不属于玩家界面。

## 7. 动效

- 动效只用于状态连续性，不用于装饰。
- 常规过渡 `120–180ms`，使用 ease-out。
- 新事件可轻微淡入或沿时间轴进入；不得弹跳、旋转或发光。
- 加载使用 1px 朱红规则线，不使用大面积 Skeleton 闪烁。
- 尊重 `prefers-reduced-motion`，关闭非必要滚动和平移动效。

## 8. 图形与图标

- 优先使用排版、边线、方块、菱形和简洁字符图形。
- 图标必须线性、几何、低细节；同一页面统一笔画粗细。
- 不把 Emoji 当作正式界面图标。
- 不为普通状态增加装饰插画。
- 角色图片未来可进入角色卡，但聊天主视图仍以姓名、首字和排版为主。

## 9. 文案

- 用世界内语言描述用户动作：例如“进入记录”“送出行动”“等待世界回应”。
- 错误必须说明业务结果：例如“内容尚未写入记录”，而不是只写“500”。
- 术语首次出现时中英并列，之后优先中文。
- 普通玩家文案避免“Projection、Manifest、Cache、ACL”等实现术语。
- 控制面文案要精确，不能用神秘措辞掩盖不可逆后果。

## 10. 无障碍

- 所有可交互元素都有可见 `:focus-visible`。
- 不只依赖颜色传达 Pending、Failed、Secret 和 Active。
- 文本与背景保持足够对比度。
- 时间线使用有序列表和语义化 Article。
- 表单具有显式 Label、错误关联和键盘操作。
- 触控目标满足移动端使用，不以极小文字作为唯一入口。
- 装饰图形使用 `aria-hidden`，状态变化使用合适的 `role=status/alert`。

## 11. 新组件验收清单

新增或修改界面前逐项确认：

1. 是否保持零圆角？
2. 是否复用既有色彩 Token？
3. 是否仍以主叙事内容为视觉中心？
4. 是否只提供必要选项？
5. 是否在桌面、平板和手机结构中都有明确位置？
6. 是否支持键盘、触控和 Focus？
7. 是否不用颜色单独表达状态？
8. 是否正确区分世界内信息、OOC 信息和控制面信息？
9. 是否避免泄露秘密存在性与内部诊断？
10. 是否通过现有构建与界面回归测试？

## 12. 禁止项

- 禁止 `border-radius` 大于 0 的常规组件。
- 禁止大面积紫蓝渐变、霓虹和玻璃背景。
- 禁止将角色消息改成左右对齐的圆角聊天气泡。
- 禁止一个页面同时出现多个高饱和主色。
- 禁止用超过三层阴影制造漂浮卡片。
- 禁止把高级设置平铺在普通玩家聊天页。
- 禁止为秘密内容显示数量型过滤提示。
- 禁止新增与“纸墨纪事”无关的独立 UI 风格。
