# 图谱失效与权威回读契约

图谱自动刷新沿用同一个数据边界：持久化失效账本、低延迟唤醒、已有 GET 的权威回读。SSE 只提示“可能有新状态”，不携带完整图谱，也不替代读取 API 的授权检查。

## 持久化是事实，通知不是

- `graph_invalidation_events` 是失效账本。写入必须与产生变化的业务事务一起提交；事务回滚则失效记录同样回滚。
- NOTIFY 仅作低延迟唤醒。通知可能丢失或合并，不得把收到通知当成持久化成功的证明。
- 订阅通过已提交的账本游标补读，断线后可以恢复；不依赖浏览器刚好在线。
- 作用域和成员授权不能由游标、通知或客户端给出的 Record 标识替代。实际内容仍经相应 GET 权限检查与可见性过滤返回。

## 前端与接口

图谱面板订阅专用 graph invalidation 流，不把 Record 事件流冒充图谱变更流。事件只触发权威 GET 回读；既有手动刷新保留。持久化、LISTEN/NOTIFY 与图谱 route 的接线都有对应的代码和 PostgreSQL 测试，不只验证本文中的字符串。

内部阶段任务书与历史评审不随 public 快照发布；它们不是运行或从干净仓库执行测试的前提。公开契约保存在此处，内部历史若存在，内部测试仍核对其原有结论，不静默重写历史。
